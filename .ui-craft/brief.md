# Product purpose

CompassNCrew presents its services and software work through a premium agency site with an optional interactive 3D portfolio journey.

# Primary user

A business owner or product lead evaluating a software partner on desktop or mobile, often in a short first-visit session.

# Principles

1. **The work is the proof.** Interactive visuals must lead to real, legible project information.
2. **Exploration is optional.** Every 3D interaction needs an automatic path and an accessible recovery route.
3. **Never strand the visitor.** Back and Home remain obvious at every point in the journey.
4. **Premium means controlled.** Use the established charcoal, cream, and amber system with restrained motion and crisp hierarchy.

# Success metric

A visitor can open the software portfolio from the homepage, view projects automatically or drive manually, and return to the referring page or homepage without confusion.

# Out of scope

- Does not replace the existing service landing page taxonomy.
- Does not introduce a second website-wide navigation system.
- Does not add unverified client claims or finished project imagery.
- Does not require WebGL to access the project index.

# Learned constraints

- **2026-08-10** — Upward overscroll at the top of services requests confirmation instead of immediately replaying the 3D workflow. Use a calm native confirmation sheet with “Stay on services” as a safe exit and an explicit persistent replay action in the services header. *Why:* accidental replay is disruptive, but intentional access to the experience must remain obvious.

- **2026-08-10** — Returning from the 2D services surface restarts the complete 3D automation sequence automatically, then restores the services surface on completion. Normal playback should finish in roughly seven to eight seconds with camera easing tuned to keep pace. *Why:* the completed static scene created a dead end and the previous replay pacing still felt slow.

- **2026-08-10** — Mobile workflow playback uses destination-aware camera framing: one active destination receives a close shot, while multi-channel fan-out uses a dedicated portrait composition that keeps every branch readable. Pulling downward at the top of the 2D services surface returns to the completed 3D workflow. *Why:* desktop fit calculations made mobile nodes too small, and the transition needed a natural reversible gesture.

- **2026-08-10** — The automation showcase is a one-time cinematic introduction, not a game or dashboard. It auto-starts one second after entry, exposes no playback controls or dense inspectors, and transitions in-place to a vertically scrollable 2D services surface after completion. *Why:* visitors need a clean visual impression first and clear commercial information second, especially on mobile.

- **2026-08-10** — Introductory copy for the automation showcase belongs to the explorable Three.js world, not a fixed DOM overlay. The visual language follows a dark navy social-automation console with portrait neon nodes, explicit channel branching, glowing directional cables, and a persistent stage rail. *Why:* fixed marketing copy obscured active nodes, while the supplied reference communicated the automation journey more directly.

- **2026-08-10** — Keep the automation narrative permanently anchored on screen during playback, complete a normal run in roughly ten seconds, and use the supplied dark eggplant studio field with a restrained lilac floor glow. *Why:* the disappearing context made the guided journey harder to follow, the previous pacing felt slow, and the brighter lavender field lacked the requested depth.

- **2026-08-10** — The automation scene uses the supplied lavender studio reference: softly lit lilac-to-purple depth, warm elevated cards, and visible contact shadows. Node identity must remain inside the node—never repeat it in a floating label—and multi-branch stages must frame every participating node during playback. *Why:* redundant floating labels and cropped branch nodes weaken comprehension and make the scene feel artificially assembled.

- **2026-08-10** — The automation workflow must preserve generous space between nodes and use a wide, horizontally explorable journey rather than forcing the complete graph into one viewport. Use dedicated cable lanes, a single medium-dark matte background, elevated warm editorial cards, and restrained data-bead signals. *Why:* fitting every node at once congested the wiring, reduced legibility, and made the interface feel mechanically generated instead of premium.

- **2026-08-10** — The 3D automation canvas needs two responsive camera states: a complete fitted overview and a guided close-up that follows active payloads. Short and long cables must both use multiple luminous packets, and completion must expose a concrete campaign deliverable. *Why:* scaling a desktop map made mobile incomplete, a single pulse was easy to miss, and analytics alone did not communicate what the workflow produced.

- **2026-08-10** — The automation showcase must read as a real workflow canvas: bright, labeled nodes with ports, directional cables, approval gates, channel branches and a feedback loop. Decorative robot characters alone are not sufficient. *Why:* visitors could not identify the previous dark scene as social media automation.

- **2026-08-09** — Mobile onboarding, driving controls, and project details must occupy distinct interface states. *Why:* overlapping controls made the first visit difficult to read and operate on narrow screens.

- **2026-08-09** — Portfolio showcases pause for three seconds in automatic mode. *Why:* five seconds felt too slow across a 20-project journey.
- **2026-08-09** — The 3D system belongs inside the CompassNCrew project and must provide both Back and Home recovery actions. *Why:* the journey is part of the business-site funnel, not a disconnected microsite.
